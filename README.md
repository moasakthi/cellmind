# CellMind

AI-assisted solar cell/panel inspection platform: a FastAPI + SQLite backend, a React
(Vite) frontend, and a standalone ML pipeline that trains an image classifier on solar
panel fault photos.

## Quick start (Windows / PowerShell)

```
.\scripts\dev.ps1            # starts backend (:8010) and frontend, each in its own window
.\scripts\seed.ps1           # (re)build cellmind.db + sample images only
.\scripts\train-model.ps1    # retrain the ml/ classifier from training_data/
```

See `scripts/` for the individual `start-backend.ps1` / `start-frontend.ps1` scripts if
you'd rather run each piece by hand. All scripts install their own Python/npm
dependencies on first run.

## Repo layout

```
backend/          FastAPI + SQLAlchemy + SQLite API (the app's data layer)
frontend/         React (Vite) UI, talks to the backend over HTTP
ml/               Standalone training pipeline for the visual fault classifier
scripts/          PowerShell runner scripts (dev.ps1, seed.ps1, train-model.ps1, ...)
training_data/    Source images (Faulty_solar_panel/<class>/*.jpg) — gitignored
BRD.MD, DDD.MD, SRS.MD, openapi.yaml   Product/design/requirements docs
```

## Backend

```
cd backend
pip install -r requirements.txt
python seed.py                          # (re)builds cellmind.db + static/images/ sample data
python -m uvicorn main:app --port 8010  # add --reload for dev
```

- `cellmind.db` (SQLite) and `static/` are generated by `seed.py` and are gitignored —
  re-run `seed.py` any time you want to reset to a clean sample dataset.
- API docs: http://localhost:8010/docs
- Covers the full `openapi.yaml` surface: batches, cells, process/equipment, cameras,
  investigations, recommendations, simulations, retraining runs, taxonomy, RBAC,
  autonomy-config, safety-constraints, audit log.
- Demo-tier simplifications (see `backend/main.py`/`seed.py` for details): single
  tenant, no real bearer-token auth (mutating endpoints take an `actingUserId` in the
  body instead), business rules BR-10 (requester ≠ approver) and BR-11 (fail-open when
  a line's cameras are all offline) are enforced against real seeded data.

## Frontend

```
cd frontend
npm install
npm run dev
```

- Runs on `http://localhost:5173` by default (Vite falls back to the next free port,
  e.g. `5174`, if that's already taken on your machine).
- `.env` sets `VITE_API_URL` — point it at wherever the backend is running (default
  `http://localhost:8010`).

## ML pipeline

Trains a ResNet18 (transfer learning) image classifier on `training_data/Faulty_solar_panel/`
(Bird-drop, Clean, Dusty, Electrical-damage, Physical-Damage, Snow-Covered).

```
cd ml
pip install -r requirements.txt
python split_dataset.py     # builds a stratified train/val/test manifest
python train.py             # two-phase fine-tune; writes artifacts/best_model.pt + metrics.json
python predict.py <image>   # run inference with the trained model
```

Last training run: **82.4% test accuracy, 0.822 macro-F1** (see `ml/artifacts/metrics.json`
for the full per-class breakdown).

The backend imports `ml/predict.py` directly (`backend/ml_bridge.py`) to run real
inference — no separate service to deploy:

- `POST /cells/{cellId}/inspect` reclassifies that cell's stored EL image with the trained
  model and persists the live result (defect probability, severity, confidence).
- `POST /inference/predict` accepts an uploaded photo (multipart `file` field) and returns a
  live classification — not tied to any seeded cell. The frontend's Inference page exposes
  this as an upload option.

Both return `503` if `ml/artifacts/best_model.pt` hasn't been trained yet (run
`python ml/train.py` first) and `422` if the image can't be read.
